UNITY WEBGL ANALYTICS INTEGRATION PROMPT
For Sick Of It Game - Umami Analytics
===============================================================================

OBJECTIVE:
Integrate Umami analytics event tracking into the Unity WebGL game to track 
game_start and level1_complete events.

CONTEXT:
The website now has Umami Analytics installed with a JavaScript wrapper that 
provides tracking functions. You need to create a C# analytics manager that 
calls these JavaScript functions using Unity's WebGL JavaScript interop.

REQUIREMENTS:

1. Create a script called AnalyticsManager.cs with:
   - Singleton pattern for easy access
   - JavaScript interop using [DllImport("__Internal")] for WebGL
   - Console logging fallback for Unity Editor testing
   - Methods to track: game_start and level1_complete (minimum)

2. Available JavaScript Functions (already on the website):
   - window.trackGameStart()
   - window.trackLevel1Complete()
   - window.trackLevel2Complete()
   - window.trackLevel3Complete()
   - window.trackLevel4Complete()
   - window.trackPlayerDeath(cause)
   - window.trackGameOver()

3. Implementation Pattern:

using UnityEngine;
using System.Runtime.InteropServices;

public class AnalyticsManager : MonoBehaviour
{
    private static AnalyticsManager instance;
    
    public static AnalyticsManager Instance
    {
        get
        {
            if (instance == null)
            {
                GameObject go = new GameObject("AnalyticsManager");
                instance = go.AddComponent<AnalyticsManager>();
                DontDestroyOnLoad(go);
            }
            return instance;
        }
    }

    // JavaScript interop for WebGL builds
#if UNITY_WEBGL && !UNITY_EDITOR
    [DllImport("__Internal")]
    private static extern void trackGameStart();
    
    [DllImport("__Internal")]
    private static extern void trackLevel1Complete();
    
    [DllImport("__Internal")]
    private static extern void trackLevel2Complete();
    
    [DllImport("__Internal")]
    private static extern void trackLevel3Complete();
    
    [DllImport("__Internal")]
    private static extern void trackLevel4Complete();
#endif

    // Public methods callable from anywhere in the game
    public void TrackGameStart()
    {
#if UNITY_WEBGL && !UNITY_EDITOR
        try
        {
            trackGameStart();
            Debug.Log("[Analytics] Tracked: game_start");
        }
        catch (System.Exception e)
        {
            Debug.LogWarning($"[Analytics] Failed to track game_start: {e.Message}");
        }
#else
        Debug.Log("[Analytics] (Simulated) Tracked: game_start");
#endif
    }

    public void TrackLevelComplete(int levelNumber)
    {
#if UNITY_WEBGL && !UNITY_EDITOR
        try
        {
            switch (levelNumber)
            {
                case 1:
                    trackLevel1Complete();
                    break;
                case 2:
                    trackLevel2Complete();
                    break;
                case 3:
                    trackLevel3Complete();
                    break;
                case 4:
                    trackLevel4Complete();
                    break;
            }
            Debug.Log($"[Analytics] Tracked: level{levelNumber}_complete");
        }
        catch (System.Exception e)
        {
            Debug.LogWarning($"[Analytics] Failed to track level{levelNumber}_complete: {e.Message}");
        }
#else
        Debug.Log($"[Analytics] (Simulated) Tracked: level{levelNumber}_complete");
#endif
    }
}

4. Integration Points:

GAME START:
- Find where the game initializes or when the player first gains control
- Add: AnalyticsManager.Instance.TrackGameStart();
- This should fire once per game session

LEVEL 1 COMPLETION:
- Find where level 1 completion is detected
- Add: AnalyticsManager.Instance.TrackLevelComplete(1);
- This should fire when player successfully completes level 1

OPTIONAL - OTHER LEVELS:
- Add similar tracking for levels 2, 3, 4 if they exist
- Use: AnalyticsManager.Instance.TrackLevelComplete(levelNumber);

5. Testing:

IN UNITY EDITOR:
- Play the game
- Check Console for: "[Analytics] (Simulated) Tracked: game_start"
- Verify tracking is called at the right moments

IN WEBGL BUILD:
- Build and deploy
- Open browser console (F12)
- Play the game  
- Look for: "[Umami] Tracked event: game_start"
- Verify events show up in the analytics dashboard

6. Build Settings:
- WebGL build with Gzip or Brotli compression
- Enable Exception Support: Full

7. Deliverables:
- AnalyticsManager.cs script created
- Script added to the scene (or uses singleton auto-creation)
- TrackGameStart() called at game initialization
- TrackLevelComplete(1) called when level 1 is completed
- Tested in Editor with console logs
- Ready for WebGL build testing

QUESTIONS TO ANSWER:
1. Where should game_start be tracked? (main menu load, gameplay start, etc.)
2. How is level completion currently detected in the code?
3. Do you have a central game manager or level manager?
4. What scene/script controls level transitions?

SUCCESS CRITERIA:
- No build errors
- Console logs appear in Unity Editor during testing
- Events track successfully in WebGL build
- No gameplay interruption from analytics code

NOTES:
- The #if UNITY_WEBGL && !UNITY_EDITOR ensures JavaScript calls only happen in WebGL builds
- [DllImport("__Internal")] tells Unity to find JavaScript functions in the browser
- Always wrap in try-catch to prevent analytics from breaking the game
- The JavaScript wrapper on the website handles checking if Umami is loaded
